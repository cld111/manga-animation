# Phase 18.4 — Batch pipeline: DINO -> Qwen -> SAM + per-stage persistence + profiling

Итоговый отчёт фазы: батч-обработка страниц, персистентность результатов этапов,
профилирование ресурсов на реальном GPU-прогоне (wind_breaker_sprint).

## Что сделано

1. **Порядок стадий изменён (18.4)**: `grounding (DINO) -> object_description (Qwen,
   один вызов на панель со ВСЕМИ её bbox) -> segmentation (SAM, ТОЛЬКО для принятых
   bbox) -> планирование -> анимация -> реконструкция (LaMa) -> рендер`.
   SAM больше не тратит инференс на отклонённые кандидаты.

2. **Батч-резидентность (`run_pages`)**: каждая модель загружается ОДИН раз на ВСЕ
   страницы, обрабатывает каждую подходящую панель каждой страницы (результаты
   сохраняются в per-page состоянии), затем детерминированно выгружается (`ModelStage`,
   ADR 0020). Никогда не грузится на страницу. `run_page_panels` — обёртка над тем же
   кодом.

3. **Персистентность этапов на диск** (`pipeline/persistence.py`): каждая модель-стадия
   сохраняет свои выходы в каталог страницы ПЕРЕД выгрузкой модели:
   - `grounding.json` — кандидаты + ObjectPlan'ы + отброшенные (dropped)
   - `descriptions.json` — полные описания Qwen (включая MotionSpec, кортежи, raw-ответы)
   - `segmentation.json` + `segmentation/<panel>__<key>.npz` — маски (точные uint8)
   Повторный вызов `run_pages` на тех же страницах загружает завершённые стадии с диска
   и НЕ загружает их модели вовсе. Убитая сессия возобновляется с последней завершённой
   стадии, а не перезапускает DINO/Qwen/SAM с нуля.

   Это закрыло реальный дефект: первый 20-страничный прогон был остановлен, и все
   результаты Qwen (хранившиеся только в памяти процесса) были потеряны — пришлось
   начинать заново.

4. **Профилировщик** (`scripts/run_phase18_4_e2e_profile.py`): фоновый сэмплер каждые
   3 сек записывает nvidia-smi (обе GPU: util/mem/power), CPU (`/proc/stat`), RAM
   (`/proc/meminfo`), диск (`shutil.disk_usage`) + события загрузки/выгрузки стадий.

## Реальный GPU-прогон: wind_breaker_sprint (2xT4 Kaggle)

Все 4 панели **PASS**, 96 кадров каждая, H.264. Итоговый JSON:
`outputs/experiments/phase18_4_e2e_single.json` (403 сэмпла GPU/CPU/RAM/Disk).

## Что это дало

- **Детерминированный fail-closed порядок**: SAM сегментирует только то, что Qwen
  приняла; принятый bbox с плохой маской всё равно отбрасывается на mask-shape гейте.
- **Возобновляемость**: любой этап можно прервать и продолжить без пересчёта готовых
  стадий (проверено тестами: второй вызов не загружает завершённые модели).
- **Измеримость**: теперь известна реальная стоимость каждого этапа — узкое место Qwen
  (68%), затем CPU-рендер (21%). Это обоснование для будущих оптимизаций (батчинг
  нескольких панелей в один Qwen-вызов, GPU помощнее для decode).
